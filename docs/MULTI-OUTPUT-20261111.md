# 多输出、高清结果与输入输出识别修复（2026-11-11）

## 已确认的问题

1. RunningHub AI 应用的多个实际发布节点曾全部归入主输出节点，丢失各自来源；同一节点多个字段时还可能归错字段。
2. 结果全部下载后，画布及历史仍固定采用第一个素材。普通图先返回时，高清图即使已保存也不会默认显示。
3. 上游的输出候选包含部分预览、控制辅助或名称包含 Output 的内部节点。内部媒体张量字段也可能被当成可上传素材。
4. 存量记录会沿用旧输出列表；模板中真实存在的高清保存节点可能未列入旧绑定。重新读取也可能继续保留旧列表。

## 修复后的行为

- 完整保留多个真实结果。RunningHub 真实节点和字段各自归属；虚拟 AI 应用输出仍兼容官方不带节点 ID 的回执。回执缺少字段时保留同一已确认发布节点的实际文件，不虚构字段归属。
- 同类图片或视频优先使用实际解码尺寸较大的结果；尺寸不足时参考同一媒体链路上的放大节点。没有证据时保留原顺序，不按文件名、数字 ID 或 URL 顺序判断高清。
- 画布、任务输出顺序及持久化历史一致使用优先结果；其他有效结果仍保留。生成历史可以切换查看和恢复不同结果，旧历史也可以优先预览已保存的高清素材。
- 正式媒体存在时跳过同节点的 preview、thumbnail、poster 子树；只有预览结果的工作流仍可读取。明确的加载节点及 input 目录文件不作为生成结果。
- 新读取合同排除有明确反证的内部节点、控制辅助和内部张量输入。保留真实保存节点、仅预览工作流、合法自定义发布节点及动态素材合同。
- 存量输出列表不完整时，仅补收原模板内精确已知的保存节点，并要求对应节点实际返回合法 output/temp 文件；不扫描任意历史节点，也不修改已接受任务的执行合同。
- 重新读取时，仅在旧绑定完整覆盖旧图普通保存端口的情况下追加新保存节点；保留已有排除分支及自定义字段。旧版分支选择会默认优先真实放大路径，显式输出选择仍生效。

结果按实际媒体类型导入，原始图片及视频不被转成通用附件，也没有在本轮增加重采样或压缩。恢复文件身份不受新增来源、尺寸元数据影响，已有完整下载不会因此重复下载。
