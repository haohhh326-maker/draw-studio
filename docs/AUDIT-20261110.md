## 已修复问题

1. **RunningHub 提交中无法及时停止。** 提交和账户检测传递取消信号；用户停止后立即结束本机等待并保存不确定提交状态。平台可能已接收时保留原记录；迟到任务 ID 会保存并尝试取消，不能把未确认的远端任务假报为已取消。涉及 `src/runninghub/client.ts`、`src/generation/pipeline.ts`。
2. **RunningHub 已完成却继续显示排队。** 完成状态缺少结果地址时显示“等待结果地址”，持续观察原任务，支持地址稍后出现和用户停止；没有增加固定查询次数上限、等待超时或自动重新提交。
3. **Muse 有结果却被旧发送标签阻挡。** 同一经过校验的回合已有可解码生成媒体时，“Still sending／仍在发送”不再挡住接收和保存。明确未确认送达、发送失败、定位不符及其他回合媒体的处理仍有独立测试。涉及 `scripts/muse-turn-anchor.ts`。
4. **目录刷新不必要地复制整份工作流。** `withBuiltinBindings` 对干净定义显式保留引用，避免原图与快照身份失效。凭证净化的默认“独立可修改副本”约定保留，执行注入也使用独立副本；RunningHub 源定义、参数选择与凭证隔离已重新验证。涉及 `src/workflow/catalog.ts`、`src/workflow/credentials.ts`。
5. **开发启动误扫描缓存网页。** Vite 依赖入口限定为 `index.html`，取消每次强制重扫，避免将 `.cache` 中的 RunningHub 页面当作应用入口。实际开发服务已启动并渲染验证。涉及 `vite.config.ts`。
6. **陈旧测试无法验证当前界面。** 更新保存状态、素材拖放、contenteditable 提示词、工作流选择器、角色与颜色断言；RunningHub 凭证测试使用隔离读取合同，保持产品的 AIFISHER 合同校验。未用修改断言的方式掩盖本轮发现的源对象修改问题。
